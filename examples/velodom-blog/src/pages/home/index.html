New to VeloDom? Start here

One page. Two files. One interaction.

Choose the Minimal JavaScript starter, keep its bootstrap and layout, then replace these two files. Open the home route and press the button: the count changes without a page reload. You do not need to learn the entire API first.

src/pages/home/index.htmlHTML
<main>
  <h1>My first VeloDom page</h1>
  <p aria-live="polite">Count: {{ count }}</p>
  <button type="button" vd-on:click="increment()">
    Add one
  </button>
</main>
src/pages/home/script.jsJavaScript
export const state = { count: 0 };

export function init({ state }) {
  state.increment = () => {
    state.count += 1;
  };
}

This website is the teaching example, not the installed framework.

Its source is examples/velodom-blog. The npm package contains the framework, portable documentation, and small editable starter templates. It does not install this entire site, its Tailwind styling, or the framework's test suite in your application.

A second consumer at examples/velodom-store proves catalog, product, guest-cart, RTL, and mock-checkout workflows with ordinary CSS. It remains separate so commerce policy never becomes framework syntax.

A structured learning path

From your first page to production boundaries.

Each lesson explains a public VeloDom capability, why it exists, and how to use it in code. The examples on this site are built from the same folders and components they teach.

A deliberate boundary

Start with HTML, local state, and one event. You do not need JSX, a global store, Tailwind, or AI. Static HTML generation is supported; automatic request-time SSR and hydration are not provided in V1.

Visible code, no hidden magic

A page is a folder. HTML is the template.

This is the core authoring contract. Route, SEO, styles, behavior, and data remain in nearby files that a beginner can find without a custom registration layer.
